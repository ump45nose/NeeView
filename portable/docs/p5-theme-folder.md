# P5 第十批：原自定义主题目录动作

## 职责与出处

固定基线 `c5c398d89` 的 `ThemeManager.OpenCustomThemeFolder`、`ThemeProfileTools.SaveFromContent` 与 `SettingPageWindow` 的“打开自定义主题文件夹”迁入现有主题设置页。已有五个预设和 `CustomThemeTemplate.json` 原字节继续复用，没有新命令、新配置文件、图片后端或读取入口。

原 `FormatManual` 是模板元数据，原设置页无独立文档按钮；保留模板中的原 URL，不将其误报为丢失的界面能力。

## 依赖与契约

- `ThemeManager.PrepareCustomThemeFolderAsync(folder, token)` 在既有单槽后台任务中完成目录准备，返回规范绝对路径；不调用系统文件管理器。
- `ThemeProfileTools.SaveFromContent` 从既有内嵌材料按原字节写出。使用 CreateNew，外部同时出现的用户样例不能被覆盖；写入后关闭流。
- `IPlatformService.OpenFolderAsync` 表达打开目录内容，与 `RevealAsync` 在父目录中定位对象分开。正式 Mac 后端使用 NSWorkspace 文件 URL 并检查系统返回值，不拼接 shell、不建立第二平台服务。
- `ThemeSettingsViewModel.OpenFolderAsync` 使用当前表单目录草稿，只转交 Engine 与宿主提供的平台契约，管理重入、取消及错误；不操作文件、不提交 Config。SettingsWindow 只负责按钮、绑定和反馈。

## 状态与资源生命周期

目录动作与扫描/加载共用 ThemeManager 单槽。启动明确动作时取消过期扫描，失败提示不被旧扫描覆盖。关闭表单取消排队准备及尚未提交的系统打开；已经开始的短样例写入等待真实完成，不假装回滚已创建目录。

流归本次准备请求所有；完成后关闭。每次动作取消源在任务 finally 释放，关闭只发出取消，避免提前释放正在使用的令牌。模型关闭或草稿目录已改变时，晚到结果不覆盖提示/列表。相同表单同时最多一个目录动作，没有长期监听或新维护线程。

## 业务规则

1. 空白目录明确报错。目录不存在时创建，然后生成 `Sample.json`；已有目录不补样例、不覆盖用户材料，沿原判断顺序。
2. 当前选择预设/自定义及配置路径保持；打开动作本身不应用草稿。成功后刷新同一主题列表，让首次样例可选；取消整个设置窗仍保留用户明确请求创建的目录/样例。
3. Finder 打开失败保留真实错误，允许重试；此前成功创建的目录和样例保持，重试不覆盖。目录创建成功但样例写入失败时，已创建目录也保持，遵守原版无目录事务回滚的边界。
4. 目录选择器、普通扫描和主题加载继续只读；仅明确按钮动作才创建文件。表单没有平台装配时，按钮禁用。
5. 原 Windows 自定义文件管理器命令行配置不套入 Mac，Mac 使用系统默认文件管理器；NSWorkspace 成功表示系统接受请求，不等于已经完成真机视觉验收。

## 错误与验收

空/非法路径、文件占据目录、创建/写入和系统打开失败均报告；关闭取消不报失败，配置和当前书页保持。已有用户文件不能被覆盖，没有对失败执行永久删除或其他回退。

测试核验首次中文嵌套目录、原模板字节及实际加载、已有空目录/用户样例、非法/文件路径、取消/独占保护；正式设置命令及真实按钮核验失败重试、取消与 Book/Page/Config 保持，模型关闭及重复动作单独覆盖。

[静默验收](../acceptance/p5-theme-folder-runtime.md)分别记录专项、全量、正式编译/ARM64构建、本地签名和系统真机边界。Headless 系统打开使用契约替身，不会激活 Finder，不当作真实 Finder 通过。

## 扩展点

完整设置搜索、实际效果/高级媒体、脚本、用户真实两分支导出、许可及正式分发继续按 P5 清单推进。目录样例已沿原能力接入，不扩展为通用模板平台。此前已跳过 P3/P4 项和 AX/NAS 未解决项保持。
