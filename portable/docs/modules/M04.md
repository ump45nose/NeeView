# M04：加载调度与缓存

## 职责

加载调度与缓存；以下描述当前实现和后续验收边界，不把设计目标当作已验收结果。

## 依赖

Application 定义调度与缓存接口；Persistence 提供磁盘缩略图实现。

## 契约

`IImageRequestScheduler.RequestAsync(source, request, priority, token)` 合并同键需求，返回调用者独立租约。`ImageCacheKey` 包含身份、版本、目标宽高及缩略图用途。
`IThumbnailCache.GetAsync/PutAsync` 可替换；当前像素缓存与优先调度由 ImageScheduler 统一协调，无独立缓存项目。

## 状态与资源生命周期

缓存按实际字节 LRU。显示租约和有等待者的条目不回收；取消只影响该调用者，最后等待者取消才中止 work。Dispose 等工作返回后释放缓存。

## 业务规则

- 当前页 → 可见 → 预取 → 缩略图；双 worker，后台最多占一个。
- 可见和通用 worker 使用独立唤醒信号，防止单个后台需求被错过。
- 512 MiB 像素、64 MiB 内存缩略图；磁盘缩略图 512 MiB。SharpCompress 按流读取，不额外常驻整包压缩数据。
- 原生晚到取消结果不能写缓存；相同 key 再次请求建立新 work，不能被旧取消任务捕获。
- 分页前后两页预取只持缓存租约，不创建显示 Bitmap。

## 错误

队列超过 512 个待处理需求返回暂不可用；磁盘缩略图 I/O 失败不阻断主图。缓存清理只作用于应用目录。

## 测试

CoreTests、NativeAndSchedulerTests、ProgressiveTests；合并、引用计数、预算、后台唤醒、取消重提、磁盘缩略图重启与版本失效。

## 扩展点

可增加自适应预算、压缩数据缓存；公开像素规格和取消语义不变。
