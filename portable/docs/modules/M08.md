# M08：状态存储与旧数据导入

## 职责

状态存储与旧数据导入；以下描述当前实现和后续验收边界，不把设计目标当作已验收结果。

## 依赖

Persistence → Application；SQLite、JSON 是具体实现。

## 契约

`ISettingsStore` Load/Save/Update；Update 在存储互斥内合并最新值。`IReaderStateStore` 保存阅读状态、历史、书签树和恢复日志。
`ILegacyImporter.PlanImportAsync/ApplyAsync` 分离预览与应用。数据库脚本 `Sql/001_initial.sql`；RecoveryOperation 新字段保存在既有 JSON 列，无隐式 schema 改动。

## 状态与资源生命周期

JSON 临时文件原子替换，DB 事务和版本化 SQL。导入前备份 settings/SQLite，批次记录决定中断后保留新配置或恢复旧配置；源只读。

## 业务规则

- nvzip/Profile 读取 UserSetting/History/Bookmark/Foldres/QuicAccess 真实文件名。
- Path 最长前缀映射，Page 保留内容定位字符串，Props 解析固定规则；数字 Page/Index 不伪造页码。
- 单图历史/书签归一为目录书籍；父子关系、自定义名称和顺序保留。
- LegacyDefaults 固定 Windows PageSortMode 顺序；差分缺省/null 恢复原默认，空字符串清空。Config.Command 输入预设先恢复，再应用自定义键位。
- 未支持配置/手势/命令进报告，脚本不执行，未映射路径保留；重复批次拒绝。
- 应用内移动重定位身份和关联书签；目标已有更新阅读记录时保留。

## 错误

16 MiB 单配置大小边界；无真实 JSON 文件拒绝，失败保留备份/恢复记录。更多历史格式需夹具确认。

## 测试

LegacyCompatibilityTests、ProgressiveTests、RecoveryTests、CoreTests；数值排序、差分键、参数、路径、树、事务、重复和身份迁移。两分支真实导出的大样本仍需 Windows 环境。

## 扩展点

版本化 DTO、增量映射、更多旧字段；未知数据继续保留到报告。
