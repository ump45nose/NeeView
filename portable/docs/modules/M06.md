# M06：布局计算与主查看器

## 职责

布局计算与主查看器；以下描述当前实现和后续验收边界，不把设计目标当作已验收结果。

## 依赖

Core 提供几何；Desktop ReaderView 转换显示资源和绘制。

## 契约

`ILayoutStrategy.Calculate(LayoutInput)` 输出 `LayoutSnapshot`。分页、连续、瀑布流共用页面尺寸和锚点；`Visible(top,bottom)` 以列索引二分查询。
`LayoutInput.Cancellation` 允许中断几何循环。`ReaderLayoutCoordinator.CalculateAsync` 链接调用方取消令牌，串行复用布局策略，新需求取消旧需求；只返回纯几何，不引用窗口或绘制对象。
ReaderView 只接收会话/调度/解码接口，公开视口、快照、缩放及滚动请求；CanvasBrush/PlaceholderBrush/SelectionBrush 是样式属性。

## 状态与资源生命周期

布局仅保存几何。可见与邻近需求拥有 CTS、租约和 Bitmap；离开范围即归还。DisposeAsync 在 Dispatcher 仍运行时取消并等待后台资源任务。
协调器拥有策略缓存和计算取消源。注册和关闭用同一互斥裁决；关闭拒绝新请求并等待全部已注册计算。检查点缓存保存页面数组副本，不保留请求取消源或阅读锚点。查看器按布局 revision 和书籍 generation 拒绝晚到结果，切书先清空旧几何。

## 业务规则

- 连续布局累计高度，未知尺寸稳定占位；尺寸补齐和视口变化按锚点补偿。
- 瀑布流默认 320 DIP/8 DIP，最短列投放，平局按方向，导航仍按内容序列。
- 单绘制控件，不按页面数创建图片控件或解码原图。双击瀑布流分页，模式锚点保存。
- 100% 是图像像素与设备像素 1:1；缩放改变请求分辨率，围绕指针补偿平移。
- 分页同步计算当前 frame；连续与瀑布流后台计算。瀑布流每 256 页保存列高度检查点，同视口/选项下根据未变前缀从检查点重排；排序、截短和尺寸晚到保持与完整计算相同的结果。
- 后台结果提交时使用最新锚点补偿计算期间的用户滚动；取消不能污染检查点缓存。可见查询耗时不代表完整重排或绘制帧耗时。

## 错误

损坏图片绘制错误占位；过期任务只释放资源；输出比例限制防止无效几何。

## 测试

CoreTests/UiTests/NativeAndSchedulerTests/LayoutCoordinatorTests；万条目几何、模式、显式选择、取消、增量与完整重排等价、快速视口变化及关闭后拒绝请求。Retina、多屏、长图帧耗时及尺寸晚到视觉补偿待真机。

## 扩展点

查看器可替换绘制实现，布局不依赖 UI。GPU 上传和布局策略替换保持锚点、取消和租约契约。
