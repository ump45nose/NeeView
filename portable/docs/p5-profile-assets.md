# P5 第七批：原 Profile 附属文件导入

当前主题运行能力由[第八批](p5-theme.md)接入；下面描述第七批的材料导入原交付边界。预览仍不应用主题/执行脚本，当前导入重建加载选中的主题。

## 职责与原出处

沿原 Exporter/Importer 将 `Playlists/*.nvpls`、`Themes/*.json`、`Scripts/*.nvjs` 接入既有预览、选择、备份、提交和窗口恢复。三个生产项目与原 JSON 状态保持；没有独立解包/恢复服务。

固定基线 `c5c398d89`：Exporter 保存三个目录的一级文件，PlaylistHub/ThemeManager/ScriptCommandSourceMap 分别枚举原扩展名；Importer 按类别显式选择并覆盖同名文件。原附属三项默认不导入。本批修正原 Windows ZIP 反斜杠假设，兼容标准 `/` 与旧 `\`。

## 依赖与契约

- Backends：ProfileImportReader 在原 SourceIo 槽读取有限字节；目录和 ZIP 返回 `ProfileImportBundle.Assets`，不按包内路径落盘。
- Engine：ProfileImportService 生成附属能力清单、独立字节候选与列表路径报告；GetAsset 返回副本。ProfileImportSelection 增加默认关闭的 Playlists/Themes/Scripts；Request 确认时再次复制选中字节。
- SaveData：Apply/Restore 共用原 `.tmp`、`.save-backup`、`.save-pending.json` 和 gate。动态清单只允许五个原根 JSON 与上述规范一级路径，旧双/三/四/五文件 marker 继续有效。
- MacOS：VM 只管理类别草稿、来源/映射代次和候选；独立 XAML 增加选择与附属报告，原文件报告仍是默认页。确认返回快照；唯一 MacApp 装配路径重建窗口。

## 状态与资源生命周期

1. 来源流按请求关闭，候选保存数据而非流或来源引用。换来源、改映射、关闭取消旧结果资格。
2. 预览及确认不改 Config.Current 或文件；主题/脚本不会注册命令、装载主题或执行 OnStartup 等事件。
3. 关闭旧窗口之前验证候选与实际目标路径；关闭/保存失败保持原窗口。
4. 旧窗口释放后，gate 内重新读取现有五 JSON，保存原五文件及实际覆盖附属项的持久备份，准备并提交同一 marker。
5. 标记之前可以取消，之后完成或回滚。部分替换失败恢复旧字节；进程中断在下次 Load 按同一受限清单恢复。
6. 重建失败仍沿 ProfileImportCoordinator 恢复整个备份后重开；失败实例不能安全释放或恢复失败时保留材料并报告。

备份位于当前 Profile/ImportBackups 的直接子目录，manifest 为规范相对文件名→SHA256/null。null 记录此前没有文件。恢复在全部路径、清单与内容哈希验证后才开始目标写入；旧五文件备份仍可恢复。恢复不删除未覆盖的材料；为暂存建立的空目录可以保留，不声称整个目录树字节等同。

## 业务规则

- 默认仍只选设置、目录参数与快速访问；附属三类需显式选择。未选择类别不覆盖，选中类别只覆盖来源存在的一级允许文件，不清空目录。
- 播放列表复用 PlaylistSourceTools 的 v1、v2 与原 alpha 版本修正规则。保持版本、顺序、重复项、别名和未知数据；无实际路径映射时保持来源原字节。唯一二进制解析入口兼容原 ReadAllText 的 UTF-8 BOM，保留 BOM 的导入文件可在 Hub 实际加载。原 Default/Pagemark 列表的 Windows 大小写别名恢复为 `Default.nvpls`/`Pagemark.nvpls` 固定逻辑名，普通文件名保持；Hub 使用既有扩展名识别，`.NVPLS` 也能出现在列表目录。
- 路径映射只处理 v1 Items 字符串或 v2 Items.Path。相对归档定位和未知字符串不替换；完整 Windows 归档逻辑 Path 只转换已映射物理前缀/分隔符。坏/未来列表在预览有明确错误；选择列表时阻止应用，不阻止同包仅导入脚本材料。
- Mac 附属落点集中在当前 Profile 三个目录。列表选中且来源存在时，将原 Config.Playlist.PlaylistFolder 恢复为默认 Mac 管理目录；配置修改与列表文件共同备份/提交。当前列表与导入文件同名时恢复实际短名（兼容 Windows 大小写/Unicode 别名），其余列表文件保持。不会跟随旧 Windows 自定义目录写入外部位置。选择与确认文案说明此适配。
- 主题保留原 JSON 字节，实际主题装载/切换尚未接入。脚本保留原 .nvjs 字节，实际执行与脚本命令仍禁用；导入/重建不执行。材料迁移不是运行能力验收。
- 目录源只枚举根与三个目录的一层，嵌套/其它扩展名报告但不读取。原 Exporter 的三个一级范围不扩展为任意文件复制。

## 错误与边界

源条目/目标/暂存/恢复路径不跟随符号链接；ZIP UNIX 链接拒绝。绝对路径、盘符、`.`/`..`、控制字符拒绝；受限路径用于写入与恢复前再次校验。规范化大小写/Unicode 同名来源或恢复清单拒绝，保存文件名不统一改大小写。

读取限额保持每文件 32 MiB、五 JSON 与附属总计 64 MiB、来源条目 10000、路径记录 100000，声明长度与实际解压量均检查。UTF-8 JSON 兼容 BOM、注释、末尾逗号；主题/脚本保持字节。NAS 原生 open 阻塞沿已有未解决边界，不由本批宣布修复。多进程/外部进程同时替换 Profile 文件没有新增原子性保证。

## 测试与验收

隔离合成 Profile 覆盖目录/两种 ZIP 分隔符只读等价、v1/v2/alpha 路径、未知/相对定位、默认/单类选择、不可变快照、唯一 Hub 加载、原字节与缺失恢复、损坏清单/hash、部分提交、重启 marker/失败重试、重建失败、路径穿越、别名冲突、链接、体积限制与取消。正式 Headless 视图检查类别双向绑定及材料能力分离，记录独立截图。

结果见[静默验收](../acceptance/p5-profile-assets-runtime.md)。构建、自动测试、Headless、设备/Windows、提交推送与发布分别报告；本批不激活应用，不操作用户图片。真实两分支导出、自定义主题执行、脚本运行、高级媒体和正式分发继续未验/待迁。

## 扩展点

未来主题/脚本能力接入必须继续区分材料与可执行能力，并补充原控制关系及安全的用户执行入口。列表修复/完整设置、真实导出与正式签名公证按 P5 清单分批交付，本批不新增维护两套配置或文件链路。
