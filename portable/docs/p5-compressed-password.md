# P5 第十六批：原压缩包口令读取

## 职责与出处

沿用固定基线 c5c398d89 的 ArchiveKey、ArchiveKeyCache、PasswordDialog 和 SevenZipAccessor 索引/抽取重试关系。在已有 ArchiveFactory/CompressedArchive 下以 SharpCompress 0.50.3 替换 Windows SevenZip，不引入第二个阅读或密码体系。

## 依赖与契约

仅明确阅读打开传入现有可等待输入回调；后台读取只能复用已验证进程缓存。ArchiveKeyRequest 增加 MayBeDamaged，界面只展示密码/加密内容损坏的歧义，不参与格式判定。根及明确嵌套 ZIP/RAR/7z 都以原逻辑路径查找口令，随机解压代理不是缓存键。

## 状态与资源生命周期

每个来源保留私有候选，固实顺序重开沿用该候选。先建立条目索引再读 Volume 属性：反序会使库的加密 RAR4 正确密码失败、RAR5 空索引。存在非空加密条目时真实抽取首项，验证及取消检查通过才允许工厂缓存；不是全包验证或画面完成。构造验证复用当前 SourceIo 槽，等待用户输入不占后台槽。

抽取仍使用请求级流及既有固实磁盘缓存；失败清理归档和本次缓存，外层拥有失败父链/嵌套代理。切书、关闭、取消和迟到输入沿原代次处理。进程 AES 缓存不写 JSON、日志或钥匙串；托管字符串按运行时回收。

## 业务规则与错误

验证普通单文件 ZIP AES/PKWARE、RAR4/5 内容及加密头、7z LZMA/LZMA2 AES 固实样本。库明确密码异常才重试；已确认加密的 RAR4 头格式错误、7z LZMA 数据错误及明文 CRC 不一致显示歧义。普通损坏包不请求密码。

RAR4 加密读取的库内 CRC 被禁用，使用库公共 Crc32Stream 累计明文校验；7z 公开非零 CRC 同样校验。RAR5 CRC 可能加密变换，不能套用 RAR4 规则。7z 数据异常类型为锁定库的 internal 类，仅比较精确类型名，不调用私有 API。

加密 ZIP 保持只读：当前 .NET 重建删除不能保留加密，不能默默移除加密。普通 ZIP 原删除能力不变。RAR/7z 原只读保持。

## 测试与扩展

八类实际夹具分别覆盖根/嵌套、错误→正确、读取/反向再次读取、缓存、原包哈希及代理释放；另有取消、迟到输入、普通坏包无弹窗、加密 ZIP 不可删除和正式拥有窗口真实解锁显示。公开夹具来源/哈希/许可见测试 Fixtures/encrypted-fixtures.json，测试口令不含用户凭据。

多卷仍不支持；同包不同口令、7z 加密头专门夹具和公开 CRC=0 情况尚未验证。首项验证不能证明后续条目完整性，后续读取失败按真实结果报错。后续媒体、效果、脚本与正式分发继续独立推进。验收见[静默记录](../acceptance/p5-compressed-password-runtime.md)。
