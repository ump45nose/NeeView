# P4 第四批：原书籍重命名与路径联动

本文件描述当批增量；当前删除、图片接收与链接范围以[P4收尾契约](p4-completion.md)为准。
沿固定基线 `c5c398d89` 的 `RenameBookCommand` → `BookControl.RenameBook` → `FileIO.RenameAsync` → `RestoreBook` 迁移。保留原实体书籍、写权限、名称编号、扩展名确认及重新加载语义；用同目录文件操作替换 Windows Shell。仍使用三个生产项目、唯一 Book/Page/BookOperation 和原 JSON，不增加身份数据库或重命名撤销栈。

## 职责、依赖与契约

- `BookOperation.CanRenameBook`：来源已打开且索引完成、写权限开启、真实目录或根归档才可执行；归档内部逻辑目录、链接、卷根及包含当前 Profile 的书籍拒绝操作。单图打开时目标是所在书籍目录。
- `RenameBookAsync(token)`：可等待业务入口。捕获 Book/加载代次，收集名称与确认后复核目标；关闭来源、改名、联动并进入唯一 `OpenCoreAsync` 恢复阅读。分类、删除及卸载不能穿插实体提交。
- `AskBookNameAsync(target)`、`ConfirmBookRenameAsync(plan)`、`RetryBookRenameAsync(message)`：宿主只采集用户选择，不访问文件或更新状态。改名失败沿原重试/取消交互。
- `IBookRenameBackend`：后台探测实体快照、规划实际新名称、执行无覆盖改名、判断恢复记录是否已提交。快照包含路径、类型、创建/修改时间及文件长度。
- `SaveData.PrepareBookRenameAsync`、`RenameBookPathsAsync`、`RecoverBookRenameAsync`、`FlushBookRenameAsync`：准备记录、更新明确引用、启动恢复及保存重试。实体已成功后不伪造文件回滚。
- `BookMementoTools.RenamePath`：仅完整来源及以 `/` 为边界的子路径替换；保持大小写，Mac 合法反斜杠不是分隔符，未知字段不猜测改写。

## 状态和资源生命周期

名称与确认不占导航锁；返回后核对当前 Book 和打开代次。准备阶段的导航锁、实体探测、名称规划及原 JSON 保存使用调用方和关闭令牌的联动取消。退出可取消尚未授权的改名，再等待其他持锁操作完成；不能出现改名等待锁、退出等待改名的死锁。

实体授权前落盘恢复记录并再次检查取消。随后失效当前原 Page 像素/封面、关闭旧来源，再执行同目录改名。实体入口使用原调用令牌；关闭只等待真实结果，不把已提交操作报告为关闭取消。失败重试等待释放导航锁，返回后重新获取并核对代次；关闭取消未确认重试。

成功或失败都通过新来源恢复，不回用已释放的 Archive。恢复原设置、条目和临时页面搜索；分割页继续沿原重新加载首半页规则，不添加第二锚点。较新的打开请求优先，即使新请求失败也不被旧改名恢复覆盖；LastBook 保留实际路径，可由用户重新恢复。页面及书籍环形历史更新引用，游标和顺序保持。

## 业务规则与前端边界

同名冲突提供未占用的 `name (2).ext` 等编号建议，并另行确认；重命名不覆盖现有实体。文件扩展名变化单独确认；文件输入默认只选主名称，目录选完整名称。Mac 文件名校验不沿用 Windows 保留设备名规则；大小写改名依据实际文件系统名称处理。

成功后更新历史、LastBook、书签、QuickAccess、每目录参数/封面路径及已登记 `.nvpls` 的明确 Path。自定义列表位于改名目录内时，列表文件地址与配置同时迁移，禁止保存时重建旧目录。保留节点身份、自定义名称、顺序、未知字段和已移除历史的抑制状态。改名不进入分类移动 Undo/Redo。

`MainWindow.DestinationFolders` 只装配名称/确认/重试回调，`MainWindow` 转交稳定命令与等待退出。主题、窗口布局及按钮可独立调整，不包含实体探测、路径替换和 JSON 保存算法。

## 错误与恢复

实体操作前在 Profile 写 `.book-rename-pending.json`；五个原 JSON 继续使用现有保存事务，各播放列表使用独立指纹与同目录原子替换。跨文件联动不是一个文件系统原子事务：部分保存成功后保留新内存路径及 marker，通过防抖、显式保存、退出或重启继续完成。

启动装配在恢复阅读前核对 marker。来源仍在且快照匹配表示未提交；目标在且快照匹配表示已提交；路径关系非法、材料损坏或身份不明确均保留记录并提示。目录恢复忽略修改时间，因为自身保存内部 `.nvpls` 会改变它；仍检查创建时间和类型，文件还检查修改时间及长度。这是有限的来源核对，不是可靠的外部移动身份关联。

缺失来源、权限不足、外部修改、目标后来被占用及列表指纹冲突不报告成功。不覆盖外部改过的列表；恢复材料损坏不能改变已知引用。实体成功而联动/重开失败明确说明当前状态，不静默回退旧路径。

## 测试、验收与扩展

`RenameBookTests` 用真实临时目录/ZIP/Profile 验证实体、阅读/搜索恢复、所有明确引用、原节点/未知字段、大小写、名称编号、扩展名取消、权限/切书/退出、失败重试、晚取消、加载代次、环形历史、保存失败及重启恢复。两处导航锁等待取消回归检查退出继续等持锁操作、没有实体调用且锁计数保持；损坏 marker 和非当前列表失败重启恢复独立验证。

正式名称/扩展名/同名对话框及命令退出在 Headless 中验证，截图离线检查。正式 ARM64 构建和严格 ad-hoc 签名独立记录；不继承为真实 Mac 焦点、Windows 动态、NAS/权限、无损 Retina 或长期性能通过。设备待项随 P3/P4 集中验收，触控板跳过、多屏无环境。
