# P5 第十一批：原设置结构化搜索

## 职责与出处

固定基线 `c5c398d89` 的 `SettingWindowModel.SettingItemRecord`、`SettingItemCommand.GetSearchText` 和 `SearchBoxModel` 为行为依据。复用 Engine 中已迁入的原 Searcher、默认 SearchContext 和 HistoryStringCollection，不增加匹配器或配置/状态体系。

范围是当前九页实际表单，以及全部235个原命令实例和已迁参数字段文案。尚未迁入的原设置页继续在P5清单中保留；这次搜索完成不表示完整原设置界面已经迁完。

## 依赖与契约

- Engine `SettingsSearchItem` 只包含目标键、页面、分区和设置文本，沿原 Page + Section + Item 聚合；仅支持原默认 text 属性。
- `SettingsSearchIndex.Analyze/Search` 使用原结构化表达式，先解析再调用 keys 重载并实体化结果，错误不能沿 string 重载静默降级为全部条目。支持取消，返回原索引顺序的纯数据。
- Mac `SettingsSearchPresenter` 从现有布局取得标题/提示，明确 `settings-section` 标识分区，不以主题/实际字号推断；不进入下拉项或虚拟列表行。命令从完整草稿集合及既有参数类型/标签取得，不维护第二字段配置表。
- `SettingsWindow.Search` 连接已有 NavigationSearchViewModel 的trim、500ms增量、明确确认、错误与关闭取消；原设置搜索历史仅在该窗口内，确认后去重前移并按原上限裁剪，删除不保存JSON。

## 状态与资源生命周期

结果直接展示同一个表单控件，命令复用原InputList行模板和ShortcutEdit实例。离开原父级前，对原本继承DataContext的控件临时固定当前上下文；归还原父级/位置后清除该本地值，恢复继承。避免脱离时短暂null回写TwoWay草稿。绑定、命名、事件和现有Apply回调不复制。

重搜先完整匹配，再归还旧结果并展示新结果。清空、导航及关闭都归还控件，按各父级中的原位置恢复顺序。非空查询进入结果页，空查询回到上一个普通页；关闭逐次搜索后手动删空仍立即返回。关闭取消待查询，晚到结果不能重挂已经关闭的表单；不存在文件句柄或新长期线程。

## 业务规则与错误

1. 原 AND/OR/NOT、词/模糊/正则等语法保持，错误提示独立于保存反馈；坏语法不改变上次有效结果，也不写确认历史。
2. 搜索结果可编辑普通字段、键位/手势和原参数弹窗。参数仍共用owner草稿，弹窗取消及整个设置取消都不提交配置。
3. 未迁命令及禁用ClearType等能力仍可检索，原可编辑性不变，不以搜索解锁未迁能力。
4. 保存仍走唯一BookOperation.ApplyOptionsAsync及原五JSON事务，失败保留同一草稿并允许重试；搜索不写配置、不刷新正文、不读取图片。
5. 搜索期间不改变普通页选择，清空恢复其显隐；选择另一个普通页立即退出搜索。保存中拒绝新的查询呈现。
