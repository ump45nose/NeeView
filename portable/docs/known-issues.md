本表记录未解决缺陷；各项通过、失败与未验范围仍以独立验收记录为准。记录问题不等于解除阶段验收条件。

## MAC-AX-001：macOS 无障碍查询持续保留回调数组

- 状态：未解决，2026-10-05 登记；P3/P4 长期资源验收失败。
- 环境：正式 Apple Silicon 应用、macOS 27.0.1、Avalonia 12.1.3；源码及修复版本见[设备记录](../acceptance/p34-device-runtime.md)。
- 复现：新进程保持同一本书、同一页，无输入、无翻页、无新解码，读取界面树 100 次；前后 gcdump 分别触发完整 GC。
- 实际结果：存活 `AvnAutomationPeerArray` 由 653 增至 27853，`MicroComShadow` 由 1208 增至 28408；页面控件、peer 及解码租约数量不变。堆图字节由 116707465 增至 132875071。
- 独立长期负载：143 循环、1573 次逐页核对、1218 秒实际浏览，RSS 五分钟中位数持续增长；采样墙钟约 38 分钟，包含空闲，不能等同持续浏览时间。
- 已定位范围：官方 macOS `recalculateChildren` 取得 COM 回调引用后未见配对 Release；静态对照确认数组保留。整个 RSS 增长的其他贡献尚未全部分离，未证明有可直接升级的修复版本。
- 当前处理：保留无障碍能力，不修改第三方二进制、不新增长期框架分支。先登记缺陷，按用户要求继续其他行为对照；长期资源项保持失败。
- 关闭条件：确定并采用可维护的修复后，重复同页无障碍查询及相同长期负载；确认完整 GC 后存活对象不持续增长、长期内存稳定，并回归界面树、焦点与弹出层行为。

数值、原始材料名称和哈希见[匿名证据](../acceptance/p34-device-evidence.json)。私人截图、Profile 和堆快照只留本机。

## MAC-FLOAT-002：Retina 浮窗关闭重开及重启后尺寸持续放大

- 状态：未解决，2026-10-05 真机复现；浮窗尺寸恢复验收失败。
- 环境：与 MAC-AX-001 相同，正式 ARM64 应用，源码 `51b8aab4d`，单个 Retina 显示器。
- 复现：在隔离原 JSON 中设置历史浮窗位置 `Normal,650,150,360,500`，启动后截图；Command+W 关闭浮窗，从历史侧栏重新打开；正常退出并再次启动。没有主动调整窗口尺寸。
- 实际结果：三次完整窗口 PNG 为 `720×1064`、`1440×1702`、`2880×1696`；截图包括窗口标题栏。正常退出保存的客户端位置依次为 `Normal,650,28,1440,1638`、`Normal,56,28,2880,1632`。高度被工作区限制，宽度继续放大。
- 定位线索：`FloatingPanelWindow.RestorePlacement` 用目标 `Screen.Scaling` 将旧物理尺寸转换为 DIP，`Snap` 用 `RenderScaling` 写回；当前真机的恢复/保存换算没有形成稳定往返。尚未独立测量两种缩放值，不能把具体根因写成已经证实。
- 已通过边界：窗口能恢复/关闭/重开；同进程重开保留搜索文本和选中历史项。文本与列表方向键不翻正文，Enter 打开历史项，Command+W 只关闭浮窗。
- 关闭条件：修复后在相同单屏 Retina 环境重复关闭/重开和正常退出/启动，客户端物理尺寸不累积变化；回归停靠/拖回、焦点和工作区限制。多屏仍需另行验收。

原始截图与隔离 Profile 位于本机 `p34-compare-20261005-142218` artifacts；匿名清单与后续对照见[本轮记录](../acceptance/p34-compare-runtime.md)。原用户 Profile 已完整校验恢复。

## MAC-READ-003：分割页缺少原版标题中的 L/R 提示

- 状态：未解决，2026-10-05 固定 Windows 与 Mac 动态对照发现；显示一致性存在差异。
- 环境：Windows 固定源码 `c5c398d89a9dd872382980769065e80c4592f4c2`，Mac 正式应用 `51b8aab4d`；同一九图 CBZ，单页、启用分割页，分别验证左右阅读方向。
- 复现：定位宽图 `003.png`，依阅读方向逐次切换两半，再进入 `004.png`。
- 实际结果：双方图像和半页导航顺序一致。Windows 标题区分 `3(R)/9`、`3(L)/9`；Mac 标题只显示书名，两半底部页码均为 `3 / 9`，状态信息也没有半页提示。Windows 底部滑条同样只显示数字，因此差异是原标题提示未迁入，不能声称原滑条包含 L/R。
- 定位线索：`Views/MainWindow.axaml:137` 的 `PageNumberView` 只绑定 `PageIndex`、`LastIndex`，未绑定运行时半页位置。该线索不表示已选定修复方式。
- 当前处理：登记显示差异，保留现有阅读行为，不在本轮改代码。
- 关闭条件：展示端恢复可识别的原 L/R 信息，回归两种阅读方向、前进/后退、整页与半页切换及排序；不能仅以数值页码不变判定导航失败。

双方截图、Mac AX 文本及文件哈希见[本轮匿名证据](../acceptance/p34-compare-evidence.json)。
