# P4 第三批：当前主页删除与系统废纸篓

沿原 `DeleteFileCommand` → `BookPageActionControl.DeleteFileAsync` → `PageFileIO` 的目标、写权限和确认规则迁移。全局命令仍只处理当前主页，没有 MultiPagePolicy；原页面列表所选页删除是另一入口，尚未迁入。仍只有三个生产项目、同一原 Book/Page/BookOperation 和原 JSON。

## 职责、依赖与契约

- `BookOperation.CanDeleteFile`：原 `System.IsFileWriteAccessEnabled` 开启、来源索引完成、普通目录真实图片及有效目标才可执行。分页取原 CurrentPage；Mac 瀑布扩展继续要求显式点击选择，滚动不更换文件目标。
- `AttachFileDeletion(IPlatformService, BitmapFactory)`：装配系统能力和唯一图像工厂。Engine 不引用 AppKit/Avalonia，也不创建窗口。
- `ConfirmDeleteAsync(path)`：表现端只呈现捕获路径并返回确认结果。原 `IsRemoveConfirmed=true` 默认值迁入；开启确认而无宿主时拒绝执行。
- `DeleteFileAsync(token)`：可等待的单主页动作。系统成功后才提交原来源集合及阅读位置，取消和失败保留页面。删除不写分类移动历史。
- `IPlatformService.TrashAsync`：正式 Mac 使用 `NSFileManager.TrashItem`，失败传播 NSError；单槽后台执行，不以永久删除回退。
- `BitmapFactory.InvalidatePage`：按原 Archive/条目 Id 移除各规格缓存及排队需求；显示租约归还前仍计费，不能提前释放。

## 状态和资源生命周期

删除忙碌状态阻止重复请求及同窗口分类/重放。原导航锁内捕获 Book/Page/加载代次/位置/模式，确认不持锁；返回后重新加锁并核对。确认期间切书、换页、关闭或撤销写权限不会删除新目标。已授权系统操作持导航锁到真实结果协调结束；其他打开可准备来源，不能提前替换当前书。

窗口命令复用既有可等待文件任务。关闭先取消尚未确认的对话框，再等待已授权系统调用、保存并释放来源。不能中断的系统调用继续占后台槽，成功后收到的晚取消不隐去真实提交。

删除成功后从 SourcePages 移除原 Page，沿原排序/搜索重建正文；优先当前序列下一图，末图退前，空目录保留同一空 Book。双页集合通过原 RebuildFrame 同步。原临时搜索保持，最后搜索结果删除后沿既有文件操作规则保留剩余全源锚点，Frame 为空且文件目标禁用；清空搜索才重新显示该锚点。空内容按原 PageHistory 规则登记空记录，不能把隐藏锚点登记成已浏览页面。原历史登记规则不接受空书，LastBook 启动快照仍更新为空。

成功后失效删除页像素/缩略需求和封面，晚到原生解码只释放。状态立即保存；保存失败明确报告文件已移至废纸篓并通过原防抖/切书/退出重试，不伪造文件回滚。系统失败不取消原阅读防抖保存。

## 界面、配置与错误

保留原 DeleteFile 命令、Delete 默认绑定及现有菜单位置。文本/对话框仍由原输入作用域隔离。设置窗口沿原左导航/右内容增加文件操作页，编辑原写权限与删除确认字段；取消不提交，失败沿既有 ApplyOptions 事务恢复。未迁入字段继续由原 JSON 合并保留。

确认窗口使用可滚动路径区域及自适应高度，长路径不挤掉取消/确认按钮。布局/主题调整不改变 Engine 目标、搜索、索引或文件操作。

缺失源、权限、废纸篓不可用、符号链接及系统错误均不能报告成功；系统不提供废纸篓的挂载来源返回错误，不回退直接删除。本批普通目录图片限定比原能力窄：原 ZIP 条目不可逆删除、快捷方式/重解析点、普通书籍页及页面列表多选继续保留未迁说明。

## 测试、设备验收与扩展

DeleteFileTests 在临时 PNG/Profile 上模拟废纸篓，实际移动自建副本验证两方向双页单主页范围、取消/失败、确认期间切书/选页/权限/关闭、成功后晚取消、末页/空书、分页和连续搜索末结果、来源消失/变链接、像素显示租约/原生晚到、保存失败、正式菜单及退出等待、设置草稿/回滚/未知字段保留。

模拟废纸篓不是 AppKit 集成验收；正式 macOS 工程编译与严格 ad-hoc 签名另行记录。真实废纸篓/权限/NAS、Mac 焦点/弹出层、Windows 动态对照、无损 Retina、长期原生内存继续随 P3/P4 集中验收。常规开发不启动或激活正式应用。
