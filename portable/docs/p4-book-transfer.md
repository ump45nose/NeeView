# P4 第九批：原整书目标菜单与实体传输

本文件描述当批增量；当前删除、图片接收与链接范围以[P4收尾契约](p4-completion.md)为准。
固定 `c5c398d89` 为出处：`BookControl.cs:212–258` 的整书复制/移动资格与调用、`DestinationFolder.cs:52–111` 的真实目标目录、两个整书菜单工厂的集合顺序与 1-based Index、`FileIO.cs:645–657,705–712,930–935` 的来源关闭/实际成功路径联动，以及 `BookMementoTools.cs:158–168` 的原引用更新。原移动入口没有调用分类 DestinationMoveService，也没有 DeleteBook 的邻项预捕获；不能凭目录监视猜测成功后会打开目标或下一书。Windows 安装包动态仍待集中对照。

## 职责、依赖与契约

- `BookOperation.TransferBookToFolderAsync`：整书真实根目录或根文件传输；单图打开形成目录书时，对象仍是整个目录。用户 `.nvpls` 只传输列表文件，引用图片保持。
- `BookTransferPlan`：原实体元数据、固定落点、完整内容指纹及原目标指纹。`IBookTransferBackend` 的后台规划/执行/恢复判定是必要替换点，不携带窗口或控件。
- `FileOperationBackend`：目录树扩展与单图片共用后台单槽、journal、临时目标、两端暂存、覆盖备份、安装和回滚。单图片协议仍拒绝目录，不通过分类栈伪装整书动作。
- `ConfirmBookOverwriteAsync`：界面只呈现整书范围并返回选择，目录覆盖明确说明全部替换、不合并。无确认宿主时拒绝覆盖。
- `SaveData`：沿原明确地址更新历史、书签、QuickAccess、目录参数、播放列表及 LastBook；复用已有 JSON 事务和 `.book-rename-pending.json`，无数据库或第二文件状态体系。

Engine 不引用平台/界面；Mac 只通过原目标菜单和可等待宿主任务调用 Engine。具体后端由唯一启动装配注入。

## 状态与资源生命周期

确认与指纹规划不占导航锁；切书、卸载和关闭取消尚未授权的准备。用户确认返回后再次核对书籍引用、打开代次、来源/目标快照与保护范围。文件动作互斥资格排除分类、删除、改名和剪贴板并发。

提交前保存原 memento、页面、搜索和锁定。移动先准备路径 marker、释放来源/图像缓存并卸载，避免归档句柄阻塞实体操作；复制保留来源与当前阅读。关闭取消准备但等待已授权实体任务；调用方取消在安装提交点前仍可生效，成功返回后必须完成真实结果联动。

后端先持久化 journal，在目标卷创建临时副本；指纹包含名称、文件内容及空目录，不跟随链接。源和原目标再次校验后分别同目录无覆盖暂存、校验、安装，完成记录先于暂存清理。跨卷阶段是验证复制，源删除发生在已验证安装后的暂存清理。文件与目录修改时间保留；单文件部分写入清理仅在仍符合本次已写字节指纹时执行。

显示租约仍由原 BitmapFactory/ReaderView 回收。没有第二来源、阅读内核、剪贴板或启动入口。

## 业务规则与明确差异

- `CopyBookToFolderAs` 固定复制，不要求源写权限；`MoveBookToFolderAs` 固定移动，沿原写权限开关。不跟随分类面板移动/复制模式。
- 手动目标按原集合顺序呈现；Index 为 1-based，0 显示菜单。不自动挑选首项，整书不使用多页参数扩大范围。
- 复制保持当前书、页面和历史路径。移动成功保持卸载，不自动打开目标或邻书；原明确地址引用跟随实际落点。两者均不加入或清空分类 Undo/Redo 栈。
- 第九批范围为普通目录及根文件（归档/用户列表）；第十一批包内逻辑书复制已按原策略接入，移动仍拒绝逻辑书。应用临时书、根链接及目录内链接明确拒绝。目录内容包含非图片与空目录。
- 自身、源内目标、祖先覆盖、类型冲突、卷根、Profile、应用临时/恢复数据拒绝。实际路径保护与后端父级别名规范化分别复核，保留文件系统大小写语义。
- Mac 同名目录当前采用**明确确认后整体替换或取消**，不做静默目录合并。Windows Shell 冲突选择尚未动态验证，不能声称两者等价。覆盖材料用于失败/中断恢复，成功清理后不能分类撤销。
- 原移动失败未发现自动重开旧书；Mac 失败恢复原 memento/页面/搜索/锁定属于记录在案的改进。

## 错误与恢复

不存在、权限/读取错误、链接/保护范围、来源或目标变化、完整性失败分别拒绝。取消/失败只回滚可由内容指纹确认的材料；外部替换、未知暂存或无法验证的部分副本保留日志，不覆盖新对象。恢复检查随机 ID、路径关系及链接。已完成目录与文件采用同一启动恢复入口。

整书移动 marker 在实体操作前写入，带原/新路径、源指纹和原目标指纹。启动装配先恢复实体 journal，再恢复原 JSON 地址；只有两端明确恢复原快照时可撤销 marker，模糊结果保留并提示。移动已成功但 JSON 保存失败，保留新内存地址/marker，通过原 FlushBookRename 保存重试，不能假装文件回滚。新打开请求优先，旧结果不能恢复或刷新新书。

进程被强制终止时，部分临时树若不能完整验证可能需手工检查。内部自定义 `.nvpls` 的联动写入会改变目录内容；中断后移动指纹不再一致时同样保守提示。没有跨进程文件身份/原子竞争保证。
