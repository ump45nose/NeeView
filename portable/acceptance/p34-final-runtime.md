## 真实 NAS 断线：失败

只新建本轮 Cache 测试目录及独立 SMB 挂载。通过本地临时代理转发到 NAS，确认实际挂载为 SMB、连接经过代理；仅中断此测试连接五秒后恢复，原有十个共享卷不参与断线。

两份合成源各为 25,171,615 字节，另有小图；分类移动尚未开始写目标，就持续停留在忙碌状态。堆栈为：

`Interop.Sys.OpenDir → Directory.EnumerateDirectories → FileOperationBackend.CanonicalDirectory → CanonicalFile → TransferCoreAsync`

代理确认断开与重连，但独立挂载随后消失，数分钟后原生目录检查仍未返回。展示方式弹出框仍可开关；Command+Q 等待文件操作，无法完成正常退出。核验源哈希完整、目标未写后，只终止该隔离测试进程，保留失败 Profile，再恢复测试前配置。登记 [MAC-NAS-004](../docs/known-issues.md#mac-nas-004nas-目录检查阻塞且重连后无法结束文件操作)。

首次操作实际落在挂载消失后的本机 APFS 路径，已撤销并核对源哈希，明确排除为 NAS 证据。`nas-invalid-local.json` 与触发记录不能作为真实跨卷/断线通过材料。

指定图片根的一个 59 图子目录随后在正式应用打开时也停在 `FolderArchive.EnumerateEntryBatchesAsync / DirectoryInfo.EnumerateFileSystemInfos / Interop.Sys.OpenDir`；同路径 Python 枚举约 0.4 秒返回。此项是新增来源读取阻塞线索，不能用以前其他样本通过推翻本次失败，也不能仅凭这个比较断定具体 .NET 或 SMB 根因。

**部分目标写入时断线、超时回滚、journal 重启恢复和重试成功尚未到达。** 不将“源未损坏”写成这些用例通过。

收尾核对本轮 NAS 目录只有两个空子目录，再逐一移除；独立挂载已消失，代理已停止。原有十个 `/Volumes` SMB 挂载仍在。

## 浮窗、焦点、弹出层与自动隐藏

历史浮窗通过原 JSON 的 `WindowPlacement` 种子启动，真实独立窗口出现；Command+W 只关闭浮窗，主 ZIP 内容保留。这个子集与前批一致，不证明真实右键浮动、停靠或拖回通过，也不解除 [MAC-FLOAT-002](../docs/known-issues.md#mac-float-002retina-浮窗关闭重开及重启后尺寸持续放大)。

普通窗口自动隐藏已启用，能看到顶部/底部隐藏、侧栏图标轨保留；为了单独测 popup 锁，测试种子设 `AutoHideFocusLockMode=0`，不代表原默认焦点锁配置。页面列表更多按钮的尝试只出现 VisualLayerManager，没有实际菜单项或可见 popup；部分坐标/右键返回 `AXError.notImplemented`，全局应用清单也遇到工具超时。上述范围保留待验，工具失败不直接登记为产品缺陷。

展示方式下拉框的真实展开与 Escape 关闭通过，取消后书籍和页位保持。随后独立复现方向键问题：先确认 AX 中下拉框的四项和选中瀑布流均存在，在 `nas-timeout` 上只按一次 Up，主书变为 `nas-reconnect`，下拉框仍展开且仍选中瀑布流。登记 [MAC-INPUT-005](../docs/known-issues.md#mac-input-005展示方式弹出层的方向键触发全局切书)。只有 AX 验证了独立 popup 窗口，主窗口 PNG 不包含该原生窗口，不能由这张 PNG 单独证明 popup 已展开。

之前将“重开、Up、Enter”连做的尝试没有在 Up 前独立观察重开状态，排除为通过材料；缺陷依据是后续逐动作核验的用例。尚未验证完整 popup 自动隐藏锁、正常停靠/拖回及所有弹出层焦点组合。

## 本地缓存绘制与屏幕性能

从用户指定子目录只读取出 12 张，保存独立本地字节副本，结束时逐文件核对本地哈希未变化。正式应用显示两列瀑布、12 项、页面缩略图及导航图，滚动后主锚点真实变化；这证明本地样本绘制/浏览，不替代本次失败的 NAS 目录打开。

新进程先遍历预热，再进行 30 次往返滚动，记录每次输入和界面观察时间，页码反复为 `1 → 3 → 6 → 3 → 1`，观察窗口 24.269 秒。Instruments 使用 Animation Hitches 附加该实际 PID；45.902 秒记录完整保存后才导出屏幕表。1261 行中有 62 行标签对应目标进程的 62 个不同应用帧，均在滚动观察窗口内，显示器为 Built-In Display 1。原始 `.trace`、TOC、显示表和分析 JSON 保留在本机。

这是间歇输入加 AX 核对的负载，不能当成持续 60Hz 滚动。显示表的 **CPU to Display Latency** 辅助指标为 N=62，nearest-rank P50=34.271ms、P95=49.254ms、最大 1156.301ms；它不含完整应用帧的所有阶段，也不等于显示占用时长或完整屏幕帧耗时。本轮未取得目标所需的完整帧指标，`screen_p95_ms=null`；不能把这个辅助 P95 写成目标通过或直接据此判定持续 60Hz 性能失败。Profiler 本身的负载也未被分离。

前一次同模板记录虽成功导出 `displayed-surfaces-interval`，1687 行中没有旧目标 PID 的呈现标签，且没有有效持续滚动负载，明确排除。`hitches-renders`、frame-lifetimes 的 duration 和其他应用的屏幕交换间隔均不等于 NeeView 的完整屏幕帧耗时。

本轮没有证明 60Hz 场景 P95 ≤ 16.7ms、首图 ≤ 1 秒或预取翻页 ≤ 100ms，也没有重跑已失败的长期内存负载。[MAC-AX-001](../docs/known-issues.md#mac-ax-001macos-无障碍查询持续保留回调数组)继续保持未解决。
