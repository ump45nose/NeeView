## 观察到的结果

| 操作 | 实际结果 |
|---|---|
| 左页面列表图标拖入右信息内容下半区 | 形成信息/页面列表上下分割组 |
| 拖组合 leader 图标到左栏 | 两个成员一起跨栏，左图标显示组说明 |
| 拖组内页面列表标题到右图标栏，再拖回左信息内容 | 成员拆组，再组合；内容与名称列表仍可用 |
| 拖动组内分隔条 | 比例随拖动变化，未改变当前阅读位置 |
| 选择图像效果入口 | 显示“图像效果将在 P5 迁入”，入口和布局保留 |
| Ctrl+1、Right、导航器适合按钮 | 原单页、反向导航和缩放重置仍可用 |
| Command+Q 后重新启动 | 恢复左信息/页面列表组、右导航器选择及 005.png / 单页 / 从右向左 |

上述组合、跨栏、拆组流程在本批正式构建中完成。最终修复后的构建另做以下复验：

- 调整左组信息/页面列表到约 67%/33%，正常退出后核对实际 `UserSetting.json`：`FileInformationPanel.GridLength=0.6701728024042074*`、`PageListPanel.GridLength=0.32982719759579265*`。重新启动后分隔位置和选中组恢复，阅读位置仍为 005.png。
- 适合窗口时合成滚动后图像仍在视口内。放大后合成滚动先改变图像可见区域，连续操作达到边界后保持图像可见；点击适合可恢复完整图片。该工具的设备特征与事件路径没有作为真实设备证据记录，因此本项不宣称真实鼠标滚轮/触控板或原 NScroll 真机边界翻页已经全部验收。
- 再次选择效果占位并返回导航器，内容和阅读位置保持。

本批发现的真实问题是精确平移能把图片推出视口；已迁入原 `DragArea.SnapView` 修复，并以自动测试验证适合窗口图片无法被巨大平移推出。原 NScroll 五模式、停顿、边界翻页与反向半页由 49 项自动测试中的专门用例验证；合成滚动不替代这些行为用例或真实设备验收。
